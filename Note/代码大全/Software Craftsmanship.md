# Software Craftsmanship
## 第三十一章 布局与风格
本章转向计算机编程的美学话题——程序源代码的布局。编排出色的代码会带来视觉和思维上的愉悦。本章介绍的技巧不影响任何的程序性能，但会让你在日后理解代码、检查代码以及修改代码变得更容易，同时使得其他人在你缺位时更容易阅读、理解和修改你的代码。
### 31.1 基本原则
本节阐述好的布局的原理
- 布局的极端情况  
  书上P730-P732给出三个例子。第一个例子是所有代码紧密排布，但是注释完备；第二个例子有分行无缩进，无分块，也没什么有用注释；第三个例子是正常代码的例子。前面两个例子展示的代码都很烂，只不过第一个例子是“极端差”。  
  
- 格式化的基本原理  
  格式化的基本原理指出，好的布局凸显程序的逻辑结构。使代码看起来有条理的最大意义莫过于展示代码结构。如果同时有两种展示代码的方式，第一种能够更好地展示代码结构，第二种使得代码更悦目，那么理应选择第一种，而且着重逻辑表现通常不会做出难看的代码（除非代码逻辑原本就丑陋）。  
  
- 人和计算机对程序的解读  
  布局是关于程序结构的有用暗示。  
    
  计算机可能只关心花括号或者begin/end；但人看程序的时总倾向于从代码的视觉外观获取提示。书P732给出一个例子，这个例子通过缩进证明了前面的观点，for循环的语句块没有使用花括号去限定其位置，因此for循环只会执行后面跟的第一行代码，然而这行代码和接下来的两行代码的缩进相同（且语义连续，看起来确实是需要被一起执行的代码），因此第一眼看上去就像for循环语句块里有三行代码一样。  
  
- 好布局有什么用  
  编程工作量的一小部分是让机器读的程序，大部分工作是写让他人（或者过段时间之后的自己）看懂的程序。如果语句按照有意义的方式布局，有助于去感知、理解和记住程序的重要特性。  
  
- 把布局作为一种信仰  
  在实践方面应当头脑开放，接受已证实为更好的布局方法，即使调整适应过程最初会感觉有些不舒服。
  
- 良好布局的目标  
  - 准确表现代码的逻辑结构  
    好的布局主要是为了展现代码的逻辑结构，一个典型的例子，程序员利用缩进等空白来表达逻辑关系。
  - 始终如一地表现代码结构  
    有些布局风格的规则会遇到许多例外，以至很难遵守。好的风格能够适应大多数情况。
  - 改善可读性
    如果有一种缩进策略合乎逻辑却令程序更难看懂，那么它就毫无用处。好的布局方案就该增强代码的可读性。
    ```个人理解
    前文提到过的“如果同时有两种展示代码的方式，第一种能够更好地展示代码结构，第二种使得代码更悦目，那么理应选择第一种”，与这条并不冲突。我认为区别在于“悦目”并不完全等于“好的可读性”，举个例子，一段精悍凝练强大的算法，改善了的性能却往往会使代码变得难以理解。
    ```
